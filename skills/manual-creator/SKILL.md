# 手册制作（Manual Creator）

为用户指定的工具创建结构化使用说明书，保存到 Obsidian vault。基于官方文档，不依赖聊天上下文；中英对照；双向链接架构；贴合用户情况。

## 工作流程

### 第一步：明确对象

确认用户要为什么工具写说明书。如果用户没有明确说，询问具体名称和版本。

### 第二步：获取官方文档

1. 搜索官方文档或 README
2. 抓取关键内容
3. 如果是 Obsidian 插件，可以从 `.obsidian/plugins/` 读取 manifest.json

原则：内容来源必须是官方文档，不依赖聊天历史。

### 第三步：编写内容

每节内容按以下模板：

```
## [英文标题 / 中文标题]

### 官方说明

> 官方英文原文
> 中文翻译

### ⚡ 小白操作

1. 第一步
2. 第二步
3. 第三步

### 💡 给你的建议

基于用户实际情况的个性化建议。
```

格式规范：
- 英文原文放 `>` 引用块，中文跟在下方
- 技术名词不强行翻译（保留 commit、repo、push 等）
- 命令、路径、代码用 `` ` `` 内联代码
- 关键功能之间用 `[[wikilink]]` 交叉引用

### 第四步：双向链接架构

- 内容超过 300 行的，拆分成多篇笔记，用 `[[wikilink]]` 连接
- 在文档目录创建索引页，汇总所有说明书链接
- 索引页放在 `认知OS/文档/` 下

### 第五步：保存

- 主文档：`认知OS/文档/[工具名] 使用说明.md`
- 子页面：`认知OS/文档/[工具名]/[子页面].md`
- 完成后用 stage_files 呈现给用户

## 质量标准

- 纯粹性：不混入聊天上下文
- 中英对照：英文原文 + 中文翻译
- 小白操作：每一步用自然语言，假设读者不懂技术
- 建议：基于用户已知情况写
- 双向链接：形成知识网络而非孤立文档
- 可维护性：每个功能点独立成节
