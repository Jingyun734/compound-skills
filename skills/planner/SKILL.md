# planner

规划skill将需求文档转化为可逐步执行的方案。

## 输入

- 评估器通过的需求文档
- 项目启动配置中的步骤约束
- 项目特定的模板：`projects/<项目名>/task-template.md`（如有）

## 执行

1. 阅读需求文档的所有条款
2. 判断任务量：小 → 单代理执行，大/复杂 → 拆为多个子代理
3. 每个子任务写清楚：目标、输入、预期产出、验收标准
4. 标注子任务间的依赖关系
5. 给出预估的时间/资源顺序

## 输出

```markdown
# Task 方案

## 总览
- 预计子任务数 / 子代理数
- 总依赖关系概要

## Task 列表
| Task | 目标 | 输入 | 产出 | 验收标准 | 依赖 | 代理角色 |
|------|------|------|------|---------|------|---------|
| 1 | ... | ... | ... | ... | - | 生成器 |
| 2 | ... | ... | ... | ... | Task1 | 评估器 |
```

## 分代理规则

- 子任务数 > 5 或有独立可并行模块 → 拆为子代理
- 子代理由 agent-interaction skill 统一调度
- 优先从 `projects/<项目名>/agent-roles.md` 获取角色定义

## 常见失败

- 任务太粗：一步包含多个不可并行的决策点
- 忽略依赖：两个有先后关系的任务写成并行
- 过度拆分：一个 task 能完成的事拆成了多个
